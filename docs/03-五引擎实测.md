# 五引擎实测（RTX 3070 · 同机同样本）

> 这一页不是官方参数摘录，是**在你本机 RTX 3070 8GB 上真实跑出来的数字**。
> 样本：两篇电缆寿命预测期刊 PDF（P1 4 页文本型 / P2 5 页扫描件）。
> 相比 README 里的估算表，这里的可信度最高——它是实测，不是公式。

---

## 一、结论先行

| 场景 | 用谁 | 理由 |
|---|---|---|
| 1048 份全量入库 | **MinerU** | 8.4 s/页最快，全本地，数据不出内网 |
| RAG 要按章节切块 | **MiniCPM-OCR**（关图表识别） | 五家里唯一输出 H2 层级 + 公式质量最高 |
| 必须保留原图 | **TeleOCR** | 唯一图片真落盘的引擎 |
| 只要纯文字 | **OXR**（云端 API） | 10.3 s/页，图必须当场拉 URL |
| 精读少量高价值文献 | **Unlimited-OCR** | 有层级但会错人名，且慢 13 倍 |

**没有赢家。** 每个引擎的强项和硬伤完全不重叠，这是选型的真实图景。

## 二、速度与质量总表

| 引擎 | 参数 | 速度 | P1 中文还原率 | P2 残留错字 | 图片 | 标题层级 | 页眉水印噪音 |
|---|---|---|---|---|---|---|---|
| **MinerU** 1.3.12 | — | **8.4 s/页** | 94.7% | **4 处**（压人模量） | 5 页只出 3 张 | 全平铺 | 1 |
| **OXR** | 1.3B | 10.3 s/页 | **98.3%** | 0 | 远程 URL，16 分钟过期 | 全平铺 | 1 |
| **MiniCPM-OCR** | 1.3B | 15.3 s/页 | 94.8% | 0 | md 空链接，但 crops 已裁出 | **H1 + 7 个 H2** | **1** |
| **TeleOCR** | 1.2B | 65 s/页 | 96.1% | 0 | **6/4 张真实 jpeg** | 全平铺 | 17 |
| **Unlimited-OCR** | — | 130 s/页 | 97.4% | 0 | 空占位符，无文件 | 两级（1×H1 + 8×H2） | 17 |

> P2 的 82–84% 系列数字**不要用来排名**。P2 是扫描件，它 PDF 自带的文本层本身就是劣质 OCR
> （`压人模量`、`围家`、`人丁程师`、英文全角 + 私有区空格 `ｍｅｔｈｏｄ\ue5e5ｔｏ`）。
> 拿坏文本层当基准算还原率，等于用错误答案对照。**真正有区分度的是「残留错字」那一行。**

## 三、每个引擎的真实表现

### MinerU 1.3.12（magic-pdf）

- **唯一全本地、数据不出内网**的方案。含核电设备型号和鉴定数据的文档只能走它。
- 最快：8.4 s/页，1048 篇约 12 小时。
- **硬伤**：扫描件上 4 处写成「压人模量」，正确是「压入模量」——而这正是论文的核心指标术语。
  走 PaddleOCR，「入/人」笔画太近判错。**术语级错字对知识库的伤害远大于普通错字：检索会漏召回，LLM 引用会传错。**
- 两篇都丢图（6→3、4→3），但**图片是下载到本地的**，这是它不可替代的点。

### OXR 1.3B

- 精度最稳：P1 还原率 98.3%，全文零错字，术语和人名都对。
- 版面坐标精准到可直接回裁 PDF，图块边界完全吻合。
- **三个必须知道的坑**：
  1. **插图链接只有约 16 分钟寿命**。`/api/v1/files/...png` 会 307 跳转到腾讯 COS 临时签名 URL
     （`q-sign-time` 到 `q-key-time` 差 960 秒）。批量跑不即时下载，Markdown 里全是死链。
  2. **标题全为 H1、无层级**（P1 9 个、P2 7 个）。RAG 切分得自己按「1.2.3」编号正则重建目录树。
  3. **本机跑不了**：官方只支持 Linux + CUDA 13 + 24GB 起。本次用的是**免费 API**
     （`https://free-oxr.somark.cn/api/v1`，无需注册）。
- 公式：式 (4)(5)(6) 编号退化成纯文本 `(4)`，只有式 1–3 有 `\tag`；一处裸写 `EAB_{i}` 漏 `$` 包裹。

### MiniCPM-OCR 1.3B

**五家里唯二做得好的地方：**

1. **章节层级**。输出 `# 中文标题` / `# English Title` / `## 0 引言` / `## 1 试验样品与方法` / `## 2 结果与讨论` / `## 3 结论` / `## 参考文献：`。对 RAG 意味着可以按章节切 chunk。
2. **公式质量最高**，能给出可直接使用的规范 LaTeX：

```
$$R=P(S>s)=\int_{-\infty}^{+\infty}f_{2}(s)\left[\int_{s}^{+\infty}f_{1}(S)\mathrm{d}S\right]\mathrm{d}s$$
$$\mathrm{EAB}_{j}=-5.48\mathrm{IM}_{j}+454.61(\pm10.20)(5)$$
```

**但有一个必须先关掉的开关 —— 这是本页最重要的一条：**

默认配置 `use_chart_recognition: true` 会**把每一张折线图转成"数据表"并编造数字**。
两份 PDF 里一个真表格都没有，它却输出了 8 个：

- P1 图 2 → `累积剂量/kGy → 压入模量 52.5 / 65.8 / …`
- P2 图 4 → `0 | 1.00 | 1.00`、`20 | 1.00 | 0.90`
- 第 6 个更露骨，直接吐出 `x_axis_label / y_axis_label`

**这些数字原文里不存在，是模型看图估的。** 入库后检索会命中它们，而且看起来比正文还"精确"。

对照实验结果：

| 配置 | 假表格 | 输出字符数 | 图片位 |
|---|---|---|---|
| `use_chart_recognition: true`（默认） | 6 | 17,892 | 0 |
| `use_chart_recognition: false` | **0** | 15,970 | **6** |

少掉的 1,922 字符**全是编造内容**。这一版才是它真实水平。

```bash
python -m minicpmvocr.cli parse doc.pdf --config config.yaml \
  --set layout.use_chart_recognition=false
```

**次要问题：**
- 图片不落盘：md 里只有 `![image]()` 空链接。图其实裁好了（`runs/*/crops/P1_page_002/008_chart.png`），
  但 md 生成器不写路径。`pipeline.save_crops=true` 只保证文件存在，不改善 md —— 需自己回填，约 10 行后处理。
- 英文标题跨行丢字：`Cables` → `bles`。

### TeleOCR 1.2B

**推翻了流行判断的三件事：**

| 流传说法 | 实测事实 |
|---|---|
| 必须 vLLM，Windows 跑不了 | 代码里有完整 `transformers` 分支（README 未更新） |
| 架构是私有 NaviOCR | Qwen2.5-VL 视觉编码器 + **Qwen3 文本解码器**（QK-Norm、无 bias） |
| 依赖 vLLM 全家桶 | 只需 transformers ≥ 4.57 |

- 权重 **2.83 GB**（2,830,223,488 字节），RTX 3070 **显存 < 8GB 跑通**。
- 两步推理：先整页布局检测（输出 `<box:x1 y1 x2 y2><label:text><内容>`），再逐块裁剪识别。
- **唯一图片真落盘**的引擎（6/4 张真实 jpeg），这对 RAG 知识库是最实际的价值。
- 代价：保留 cnki 水印（17 处）、65 s/页（比 MinerU 慢 8 倍），只宜精修不宜批量。

**两个坑（都已在本次实测中定位并修复）：**

1. **`padding_side` 默认 right，batch>1 会污染短序列**。P1 首页英文标题块吐出 2028 字符的
   `of 100mls of 100mls…` 重复幻觉。同一 bbox 单独跑（batch=1）输出完全正确。
   **改成 `padding_side="left"` 后重跑，157 个块零异常。**
2. **`max_new_tokens=None` 会退化成 `max_length=128000`**，模型会一直生成。必须手动设。

另注：`layout_image_size=(1036,1036)` 会把 A4 竖版硬拉伸成正方形（纵向压 56%），官方默认值。

### Unlimited-OCR

- 标题层级做得最好（1 个 H1 + 8 个 H2），术语也对。
- **把人名「乌晓燕」认成「马晓燕」** —— 人名错误比术语错误更难被下游发现。
- 17 处页眉页脚混入正文；图片只输出 `page2_131_627_461_798.jpg` 这种坐标占位符，**一张都不裁**。
- P1 里丢了 γ：「高温与 γ 射线」变成「高温与射线」。
- 慢 13 倍（130 s/页），全量 1048 篇要 40 小时。

## 四、附带发现：MiniCPM-OCR Jev（2B 质检器）

这是五个解析引擎之外的第 6 个模型，**而且是解决"批量跑完谁来复核"这个问题的唯一答案**。
已补进 `data/models.csv`。

| 项 | 情况 |
|---|---|
| 权重 | `openbmb/MiniCPM-OCR-Jev-gguf`，Q4_K_M **1.27 GB** + mmproj **0.67 GB** |
| 参数 | 2B |
| 功能 | 输入「原图 + OCR 候选」，输出 0–1 一致性分 |
| 跨引擎 | 对 MiniCPM / GLM-OCR / PaddleOCR-VL / Xiaomi-OCR 输出 AUROC 稳定 **91.9–93.4** |
| 判别力 | 同一张图 + 两个候选：ground_truth **0.995** vs 错序版 **0.007** |
| 后端 | 官方支持 llama.cpp `llama-server` **和 Ollama**（`sdk/jev_score/ollama_backend.py`） |
| 协议 | `QUESTION = "consistency"`，llama-server 暴露 `/v1/systemone` 直接返回类别概率 |

**机制上最关键的一点**：Jev 需要**两张图** —— 原图 + 「把候选文本渲染回图像」的渲染图，
然后用视觉方式比对一致性。这正是它能跨引擎评分的原因：**绕开了各引擎 tokenizer 的差异**。

**Windows 上的落地路径**：官方 render 服务是 Linux only 且依赖 Chromium。
用 Pillow 自建渲染器（尺寸自适应、离线、快）即可替代，需做基础 LaTeX 降级清理。
注意 `\in` 会抢先匹配 `\notin` 的子串，**按命令长度降序替换**即可修复。

**对 1048 篇批量场景的直接价值**：这是一个"哪些页需要人工复核"的自动分诊器。
OXR、MinerU、Unlimited-OCR、TeleOCR 四家都没有这个能力，只能全量人工抽查或全盘信任。

## 五、仍然完全未验证的维度：表格

**五个引擎，一个都没测到表格。**

两篇样本 PDF 是纯图无表（「表 1」零命中）。MiniCPM 输出的那 8 个"表格"是图表幻觉，不是真表格。

所以以下能力**全部没被验证**：

- OXR 宣称的 OmniDocBench TEDS 97.18 / 表格解析全球第一
- MinerU 的 RapidTable
- MiniCPM 的真表格能力
- TeleOCR 的 OTSL 结构化输出

这是当前选型最大的空白。**测法**：给 3–5 份含合并单元格、多层表头的 PDF，一晚上能补齐这一列。

## 六、环境变更记录（重要）

为了跑通 TeleOCR，base conda 环境的 transformers 从 **4.49.0 升到 4.57.5**（tokenizers 0.22.2）。

已验证：
- MinerU（magic-pdf 1.3.12）仍可正常 import
- 之前为 UniMERNet 打的 `cache_position` patch 还在（第 2185 行）

如需退回 4.49，TeleOCR 就得改成手工重映射权重 key（`visual.*` → `model.visual.*`，
`model.layers.*` → `model.language_model.layers.*`，这套 conversion mapping 是 4.57 才有的机制）。

## 七、可复用的安装/配置坑（Windows 专用）

| 坑 | 正确做法 |
|---|---|
| Ollama 装不上，静默参数无效 | Ollama 用 **NSIS** 不是 Inno Setup。参数是 **`/S`**，不是 `/VERYSILENT`。加 `MSYS_NO_PATHCONV=1` 防止 Git Bash 把 `/S` 当路径转换 |
| magic-pdf 找不到模型 | 包名是 `magic-pdf`（MinerU 1.x），不是 `mineru`。搜 `mineru*` 会漏 |
| magic-pdf `models-dir` 报 TypeError | 1.3.12 要**字符串**；字典是 MinerU 2.x 格式 |
| 默认走 layoutlmv3 要 detectron2 | 配置里补 `layout-config` + `device-mode: cuda`，走 DocLayoutYOLO |
| OCR 模型版本对不上 | 代码要 `ch_PP-OCRv3_det_infer.pth`，仓库只给 v4/v5/v6，改映射指向 v5 |
| UniMERNet 与 transformers 4.57 冲突 | `cache_position` / `EncoderDecoderCache` 不兼容，需改源码加 `**kwargs` |
| PP-DocLayoutV3 找不到轻量后端 | `ppdoclayout3_torch` 要 HF 格式权重，官方只发 Paddle 推理 tar。改用 **CPU 版 paddlepaddle（约 100MB，GPU 版 900MB）**，单页 5 秒够用 |
| `magic-pdf.exe` 被系统拦截（126） | 绕过 exe，直接用 Python 入口点调用 |
