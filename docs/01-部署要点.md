# 逐个模型的 3070 落地要点

> 只写"在 8GB 卡上跑起来"真正需要的东西：仓库地址、推荐档位、启动命令、已知坑。
> 标 ✅实测 的条目数字来自本机 RTX 3070 实跑，详见 [03-五引擎实测.md](03-五引擎实测.md)。

---

## A 档（开箱即跑）

### HunyuanOCR（1B）

- 权重：https://huggingface.co/tencent/HunyuanOCR
- 推荐档位：BF16
- 坑：原生分辨率视觉编码器，**长边越大视觉 token 越多**。3070 上单图长边建议 ≤1600px。

### GLM-OCR（0.9B）

- 权重：https://huggingface.co/zai-org/GLM-OCR ｜ 文档：https://docs.bigmodel.cn/cn/guide/models/vlm/glm-ocr
- 推荐档位：BF16（官方标称运行显存 4GB）
- 支持：vLLM / SGLang / Ollama / MLX —— **四家里唯一给全了端侧路径的**
- 吞吐：PDF 1.86 页/秒、图像 0.67 张/秒（官方，非 3070 环境）

```bash
ollama run glm-ocr          # 最省事
```

### Qwen3-ASR-0.6B（0.94B）

- 权重：https://huggingface.co/Qwen/Qwen3-ASR-0.6B
- 推荐档位：Q8_0（811MB）或 BF16
- 优势：128 并发下 RTF 0.064；中文普通话 CER 5.2%，粤语 10.2%
- 坑：**不做说话人分离、不给时间戳**。要时间戳得配 `Qwen3-ForcedAligner-0.6B`（额外 0.9GB）

```bash
vllm serve Qwen/Qwen3-ASR-0.6B --gpu-memory-utilization 0.6 --max-model-len 2048
```

### MiniCPM-OCR Jev（2B，质检器）

- 权重：`openbmb/MiniCPM-OCR-Jev-gguf`（ModelScope 有官方镜像，HF 国内常打不开）
- 推荐档位：**Q4_K_M 1.27GB + mmproj 0.67GB**（合计 1.94GB）
- 作用：输入「原图 + OCR 候选的渲染图」，输出 0–1 一致性分。**跨引擎通用**，可给任何引擎的输出打分
- 判别力：同一张图 + 两个候选，ground_truth 得 0.995、错序版得 0.007
- 后端：官方同时支持 llama.cpp `llama-server` 和 **Ollama**（`sdk/jev_score/ollama_backend.py`）
- 协议：`QUESTION = "consistency"`；llama-server 暴露 `/v1/systemone` 直接返回类别概率
- **Windows 落地要点**：官方 render 服务是 Linux only 且依赖 Chromium。用 Pillow 自建渲染器替代
  （尺寸自适应、离线、快）。LaTeX 降级时 **按命令长度降序替换**——否则 `\in` 会抢先匹配 `\notin` 的子串

## B 档（可行，但要限制输入）

### MiniCPM-OCR 1.0（1.3B）✅ 实测 15.3 s/页

- 仓库：https://github.com/OpenBMB/MiniCPM-OCR ｜ GGUF：https://huggingface.co/openbmb/MiniCPM-OCR-1.0-gguf
- 推荐档位：Q8_0（0.812GB）+ mmproj f16（0.901GB）/ 或 Ollama Q4（504.6MB + 859.3MB）
- **实测优势**：五家里唯一输出 H2 章节层级（`## 0 引言` / `## 1 试验样品与方法` / …），公式质量最高
- **坑 1（最贵）**：默认 `use_chart_recognition: true` 会把折线图转成"数据表"并**编造数值**。
  两份无表 PDF 输出了 8 个假表，1,922 字符全是编造。**入库前必须关**
- **坑 2**：`--mmproj` 只有 4× 变体，没有 16×；不传 `--mmproj` 直接报错
- **坑 3**：完整 PDF 需 PP-DocLayoutV3 版面模型。轻量后端 `ppdoclayout3_torch` 要 HF 格式权重（官方只发 Paddle tar），
  走不通。**改用 CPU 版 paddlepaddle（约 100MB，GPU 版 900MB）**，单页 5 秒够用
- **坑 4**：md 里图片是 `![image]()` 空链接，但 crops 其实已裁好（`runs/*/crops/P1_page_002/008_chart.png`）。
  `pipeline.save_crops=true` 只保证文件存在，不改善 md —— 需自己回填，约 10 行后处理

```bash
# 必须关掉图表识别
python -m minicpmvocr.cli parse doc.pdf --config config.yaml \
  --set layout.use_chart_recognition=false

# 纯 llama.cpp 路线
llama-server --model MiniCPM-OCR-1_0-Q8_0.gguf \
  --mmproj mmproj-model-f16-4x.gguf \
  --ctx-size 8192 --n-gpu-layers 999 --port 18499
```

### TeleOCR（1.2B）✅ 实测 65 s/页，2.83GB 权重

- 仓库：https://github.com/caipeng328/TeleOCR ｜ 权重：https://www.modelscope.cn/models/XingChen-AGI/TeleOCR
- **推翻流行判断**：不需要 vLLM，不需要 Linux。代码里有完整 `transformers` 分支（README 未更新）
- 架构：**Qwen2.5-VL 视觉编码器 + Qwen3 文本解码器**（QK-Norm、无 bias）。需 `transformers >= 4.57`
- 唯一优势：**五个引擎里唯一图片真落盘的**（6/4 张真实 jpeg）
- **坑 1（致命）**：`padding_side` 默认 right，batch>1 会污染短序列，吐出 2028 字符的
  `of 100mls of 100mls…` 幻觉。**改 `padding_side="left"` 后 157 个块零异常**
- **坑 2**：`max_new_tokens=None` 会退化成 `max_length=128000`，模型一直生成，必须手动设
- 坑 3：`layout_image_size=(1036,1036)` 会把 A4 竖版硬拉伸成正方形（纵向压 56%），官方默认值
- 代价：保留 cnki 水印（17 处），速度是 MinerU 的 8 倍慢，只宜精修不宜批量

```bash
python infer.py --image_sub_path ./in --result_save_path ./out \
  --use_async --override model_path=./models/TeleOCR \
  BACKEND="transformers" LAYOUT_MODE="Detection" \
  MAX_PIXELS=1280000
```

### LFM3-1.7B / LFM3-Audio-2B（1.73B / 2.0B）

- 家族页：https://huggingface.co/collections/LiquidAI/lfm3
- 推荐档位：Q4（文本约 1GB）/ Q8
- 格式最全：GGUF、MLX、ONNX、FP8、NVFP4 五种都有
- 坑：**LFM Open License v1.0，年营收 1000 万美元以上需单独谈**，不是标准开源

### Qwen3.5-2B（2.27B）

- 权重：https://huggingface.co/Qwen/Qwen3.5-2B
- 推荐档位：Q4_K_M（1.28GB）
- 注意：这是**原生多模态**模型（带视觉编码器），不是纯文本
- 坑：262K 上下文是卖点也是陷阱，长上下文下 KV 才是主要占用

```bash
ollama run hf.co/unsloth/Qwen3.5-2B-GGUF:Q4_K_M
```

### GLM-ASR-Nano-2512（1.5B）

- 仓库：https://github.com/zai-org/GLM-ASR ｜ 权重：https://huggingface.co/zai-org/GLM-ASR-Nano-2512
- 推荐档位：BF16
- 优势：**方言 + 耳语（低音量）专项优化**，这是它相对 Qwen3-ASR 的差异点
- 坑：依赖 `transformers 5.0.0`（需源码安装）；2025-12-27 前下载的权重格式已过期，要重拉

### Cohere Transcribe 03-2026（2.1B）

- 权重：https://huggingface.co/CohereLabs/cohere-transcribe-03-2026（**gated，需登录同意**）
- 推荐档位：Q8_0（2.05GB）走社区 GGUF，或 BF16 走 Transformers
- 优势：Open ASR Leaderboard 第一，平均 WER 5.42%
- 坑 1：**不做语种检测**，必须显式传 ISO 639-1 语言码
- 坑 2：无时间戳、无说话人分离
- 坑 3：>35s 自动切块拼接，长音频要留意接缝

### Qwen3-VL-Embedding-2B（2.1B）

- 权重：https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B
- 推荐档位：BF16（权重 4.4GB）+ `batch_size=1`
- 优势：双塔无自回归 KV 增长，显存几乎不随序列长度涨
- 坑：**vLLM 需 ≥ 0.14**；batch 是唯一显著变量，3070 上 batch 别超过 4

## C 档（边缘，必须量化）

### FireRed-OCR（2.13B）

- 仓库：https://github.com/FireRedTeam/FireRed-OCR
- 推荐档位：**FP8 / Q4**（BF16 在 3070 上峰值 6.0–7.2GB，贴边）
- 底子是 Qwen3-VL-2B-Instruct，三阶段训练（预对齐 → SFT → 格式约束 GRPO）
- 坑：官方写"推荐显存 ≥8GB"，正好卡在 3070 边界，实际要限分辨率

### Granite Speech 4.1 2B（2.3B）

- 权重：https://huggingface.co/ibm-granite/granite-speech-4.1-2b
- 推荐档位：**Q4_K_M（2.14GB，官方估 3GB）**，BF16 需 6GB
- 优势：**官方给了完整显存表**（BF16 6GB / Q8 4GB / Q6 4GB / Q4 3GB），透明度最高
- 额外能力：关键词列表偏置（KWB），适合专业术语场景

### Qwen3-ASR-1.7B（2.3B）

- 权重：https://huggingface.co/Qwen/Qwen3-ASR-1.7B
- 推荐档位：**FP8（2.5GB）** 或 Q8
- 优势：Clean WER 5.76%（优于 Whisper-large-v3 的 7.44%），30 语种 + 22 种中文方言
- 坑：长音频编码器序列长，峰值随时长上升；BF16 8K ctx 估算 6.4GB

## D 档（3070 不可行，但云端可用）

### OXR-1.0（1.3B）✅ 实测云端 API 10.3 s/页

- 仓库：https://github.com/SoMarkAI/OXR
- **本地不可行**：官方要求 Linux + CUDA 13 + 24GB 起、推荐 48GB，且无 llama.cpp / Ollama / LM Studio 路径
- **但免费 API 现成可用**（无需注册）：

```bash
pip install somark
somark --base-url https://free-oxr.somark.cn/api/v1 --api-key dummy \
  parse doc.pdf --formats md,json --out ./oxr-out/
```

- 实测表现：还原率 98.3%、零错字、术语和人名全对、版面坐标可精准回裁
- **坑 1（最贵）**：图链只有约 **16 分钟寿命**。`/api/v1/files/...png` 会 307 跳转到腾讯 COS
  临时签名 URL（`q-sign-time` 到 `q-key-time` 差 960 秒）。批量跑必须当场下载
- 坑 2：标题全为 H1、无层级，RAG 切分要自己按「1.2.3」编号正则重建目录树
- 坑 3：式 (4)(5)(6) 编号退化成纯文本 `(4)`，只有式 1–3 有 `\tag`；一处裸写 `EAB_{i}` 漏 `$` 包裹
- 许可：自定义协议（Apache 2.0 + 额外条款），商业使用在融资/年营收 ≤200 万美元内免授权

### VoxCPM2（2.3B）

- 仓库：https://github.com/OpenBMB/VoxCPM，权重 https://huggingface.co/openbmb/VoxCPM2
- **BF16 实测峰值 7.3–7.9GB，超 3070 可用 7.2GB → OOM**
- 3070 上必须降档：q8（2.3GB）或 4-bit（1.1GB）
- 坑 1：运行时是自研 `voxcpm` 库，**不走 transformers**，部署路径要单独规划
- 坑 2：streaming 要求更高，3070 上放弃 sub-100ms 实时
- 坑 3：voice design 输出每次不同，要多次采样挑结果

## 附：Windows 环境通用坑

| 坑 | 正确做法 |
|---|---|
| Ollama 静默安装无效 | Ollama 用 **NSIS** 不是 Inno Setup。参数是 **`/S`**，不是 `/VERYSILENT`；加 `MSYS_NO_PATHCONV=1` 防路径转换 |
| MinerU 1.x 找不到 | 包名是 `magic-pdf` 不是 `mineru`，搜 `mineru*` 会漏 |
| magic-pdf `models-dir` 报 TypeError | 1.3.12 要**字符串**；字典是 MinerU 2.x 格式 |
| 默认走 layoutlmv3 要编译 detectron2 | 配置补 `layout-config: doclayout_yolo` + `device-mode: cuda` |
| `magic-pdf.exe` 被拦截（126） | 绕过 exe，直接用 Python 入口点 |
| 装 PyPI 包把 torch 升级了 | 一律 `pip install --no-deps` 后手动补依赖 |
